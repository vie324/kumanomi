# くまのみ 統合ポータル

**社内SNS × 経営ダッシュボード × 業務システムを1つに束ねた、くまのみ整骨院・整体院グループのためのオールインワン・ポータル(動作するプロトタイプ)**

ジンジャー(勤怠)・サンクスギフト/TUNAG(社内SNS)・Salon One(予約)・スプレッドシート管理を、
1つの統合ダッシュボードに置き換えることを目的としたデモアプリケーションです。

## 🚀 動かし方

ビルド不要・外部依存ゼロの静的アプリです。

```bash
# リポジトリ直下で
node scripts/gen-config.js   # 接続設定(config.js)を作る。環境変数なしならデモモード
python3 -m http.server 8080
# → http://localhost:8080 を開く
```

`config.js` は Git 管理外です。生成せずに開いてもデモモードで動きますが、
ブラウザのコンソールに `config.js` の 404 が出ます(動作には影響しません)。

**GitHub Pages でそのまま公開できます**(Settings → Pages → Branch を選ぶだけ)。

- データはすべてブラウザ内(localStorage)で完結するデモデータです。日付は常に「今日」を基準に自動生成されます。
- 右上の ⚙️ から「デモデータをリセット」できます。
- 🌙 ボタンでダークテーマに切り替わります。モバイル表示にも対応しています。

## 🔐 権限と組織図について

**組織図(傘)が「誰に何が見えるか」を決めます。** 自分の傘の下(配下)にある日報・情報はすべて見えます。管轄は毎月変わる前提のため、**組織図ページでカードをドラッグするだけで付け替え**でき、見える範囲に即時反映されます。

```
社長(熊野)
└ 統括マネージャー(小林)
  ├ マネージャー(加藤)─ 統括院長(大森)─ 院長:成増・大宮
  ├ マネージャー(高木)─ 院長:川越・浦和 / 店長:ビューティー大宮
└ 本部人事(森)… 全店舗の勤怠・シフト(日報は対象外)
  └ 事務職員(青木)… 給与関連(勤怠・経費・交通費・発注)の最終確認
```

- **呼称は店舗カテゴリで自動で変わります**:整骨院・整体院・鍼灸院=院長 / 美容・エステ=店長
- **メンター制度**は組織図と別レイヤーで重なります。メンターは担当メンティーの日報も閲覧できます(組織図ページの「🌱 メンター関係」トグルで可視化)
- 組織変更はすべて**変更履歴**に残り、ワンクリックで元に戻せます
- 画面右上のユーザー名から**ログインユーザーを切り替えて**、役職ごとの見え方をその場で確認できます

主なルール:
- **顧客情報・カルテは出勤打刻をしないと閲覧できません**(個人情報保護)。院長・店長以上は緊急対応のため打刻なしでも閲覧できますが、警告バッジが表示されます。
- **シフトは全社員が全店舗を閲覧でき、編集は院長・店長以上**(自分の傘の下にある店舗のみ)。**必要人数ルール・充足判定・他スタッフの希望休の提出状況は責任者のみ**に表示されます。
- **希望休は月単位で申請**します(希望休・有給休暇・特別休暇・誕生日休暇から日ごとに選択)。**日ごとの理由も一緒に提出**でき、責任者は提出状況の行をタップして**申請内容(日付・種別・理由)を確認**できます。
- **給与確認ページは事務職員・本部人事・統括マネージャー以上のみ**。勤怠・経費・交通費・発注を1欄で最終確認し、CSV(Excel)で書き出せます。そのまま**社労士へ提出**(給与連絡表フォーマット)まで行えます。事務職員は日報の閲覧対象外です。
- **日報は傘に沿って下りていく形**で見えます。各行に「なぜ見えるか」(自分/メンティー/直属/配下/全社)のバッジが付きます。
- **売上・経営数値は全員が閲覧できます。**
- **テスト点数・スキルスコア・評価は本人と責任者(院長以上)のみ**。一般スタッフに他のスタッフの点数は表示されません。
- **勤怠の承認キューは責任者のみ**。一般スタッフの勤怠画面は打刻と自分のサマリー(出勤日数・遅刻)だけのシンプルな表示です。
- **在庫の発注・入荷は院長以上のみ**(一般スタッフは閲覧のみ)。経費の承認も院長以上です。

## 🤖 AI 機能について

デモでは `js/ai.js` が擬似的に応答を生成しています。実運用では同ファイルを **Claude API 等の LLM 呼び出しに差し替えるだけ**で、以下がそのまま本物になります:

- シフト自動作成(希望・必要人数・研修の制約充足)
- ボイス入力の書き起こし → SOAP カルテ整形
- カルテ+写真 → 患者様向け LINE メッセージ生成
- 面談メモ → 問題点・要因・ネクストアクションの構造化
- 会議メモ → 議事録・決定事項・アクションアイテム化
- 研修テーマ → テスト問題の自動生成
- ロープレ音声 → トークスクリプトとの比較採点・フィードバック(音声認識 + LLM 評価)
- 社内 FAQ チャットボット

## 🗄 本番環境(Supabase)への移行

**第1段階として、店舗・メンバー・組織図を Supabase に登録できるようにしました。**
詳しい手順は [`docs/supabase-migration.md`](docs/supabase-migration.md) を参照してください。

```bash
# 1) スキーマを作る — Supabase の SQL Editor に setup.sql を貼って Run するだけ
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/setup.sql

# 2) 組織図を登録する(全店舗・全メンバー・傘が一度に入る)
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/seed/0001_roster.sql

# 3) 確認
psql "$DATABASE_URL" -c "select repeat('  ', depth) || full_name || ' 【' || role_title || '】'
                           from public.v_org_tree order by sort_path, name_path;"
```

- 組織図スプレッドシート(統括MG / MG / 統括院長 / 店舗 / 院長 / 整体部門 / 受付スタッフ / 店長 / 美容部門)を
  **そのまま貼り付けるだけ**で取り込めます。結合セル・2行見出し・部門ごとの列数の増減に対応しています。
- **氏名をキーに UPSERT する**ので、毎月の組織変更は更新したシートを貼り直して再実行するだけです。
- 画面(`組織運営 → メンバー・組織図の一括登録`)からは、
  **スプレッドシートのセルの色から資格・性別を自動判定**して取り込めます。
- 権限(RLS)は `js/auth.js` と同じ形を SQL 側にも実装しています。

### 接続先の設定(Vercel)

Vercel → Settings → Environment Variables に 2 つ入れるだけです。
ビルド時に `scripts/gen-config.js` が `config.js` を書き出し、アプリがそれを読みます。

| 変数名 | 値 |
| --- | --- |
| `SUPABASE_URL` | `https://xxxxxxxx.supabase.co`(Settings → API → Project URL) |
| `SUPABASE_ANON_KEY` | Settings → API → Project API keys → **anon public** |

> **service_role キーは絶対に設定しないでください。**
> RLS を迂回するキーなので、ブラウザに配ると誰でも全データを読めてしまいます。
> 誤って設定された場合、`gen-config.js` がビルドを失敗させます。

環境変数が未設定のときはデモモード(端末内のみ)でデプロイされます。
未設定のまま本番に出したくない場合は `KUMANOMI_REQUIRE_SUPABASE=1` を足すと、
接続先が無いビルドを失敗させられます。

### データの流れ(案B:ローカルキャッシュ + 背面同期)

画面は `js/store.js` だけを見ます。localStorage も Supabase も直接は触りません。

```
画面 ──▶ store.load(...)   … 必要なデータをそろえる(非同期の入口)
     ──▶ store.get(...)    … そろったキャッシュを読む(同期)
     ──▶ store.update(...) … 端末に即反映し、送信は裏側で
                                 │
                          js/sync.js(送信キュー・再送・取得)
                                 │
                              Supabase
```

- 入力はまず端末に保存され、画面はすぐ次に進めます。通信は裏で行われます。
- 電波が切れても操作を続けられ、つながり次第まとめて送信されます(未送信件数はヘッダーに出ます)。
- 更新は **変えた項目だけ** を PATCH で送るため、同じレコードを別々の項目で直しても打ち消し合いません。
  同じ項目を同時に直した場合は後勝ちです。
- 権限エラーなど何度送っても通らない変更は 3 回でキューから外し、
  「接続とデータ」画面に理由付きで記録します(キューが詰まりません)。
- 各ページは `needs: ["attendance", "staff"]` のように必要なデータを宣言し、
  ルーターがそろえてから描画します。

**あとから案A(全面非同期・常にサーバーを見る)へ移す場合**、画面は 1 行も変えずに済みます。
`store.load()` の中身を「キャッシュを返す」から「毎回サーバーから取る」に変え、`js/sync.js` を外すだけです。
そのために、画面から同期的に読んでよいのは `load()` 済みのコレクションだけ、という約束を守ってください。

### ログイン

接続先が設定されているときだけ、起動時にログイン画面が出ます(未設定のあいだはログイン不要のまま)。

**最初の1人**は、Supabase の Authentication でユーザーを作ったあと、SQL Editor で次を実行します
(名簿を登録できる人自身が、最初は名簿に居ないため)。

```sql
select public.bootstrap_admin('admin@example.co.jp', '管理 太郎');
select * from public.v_login_status;   -- 紐付き状況の確認
```

- メールアドレスとパスワードでログインし、`public.me()` で自分が名簿のどの行かを社員番号で特定します
- 名簿と紐付いていないアカウントは、**別人として入らせず**にその旨を表示してログアウトします
- アクセストークンは期限が近づくと自動更新されるので、業務中に勝手にログアウトされません
- 本番ログイン中はデモ用のユーザー切替を出さず、アカウント情報とログアウトのみになります

### みんなで使う部分(投稿・タスク・チャット・研修・始末書・予算)

`0009_collaboration.sql` で、アカウント同士が連動する部分をサーバーへ移しました。
社内SNS・タスク・チャット・研修レポート・始末書は、**別のアカウントで入っても同じ内容**が見えます。

| 画面 | サーバー側 | 誰が読めるか |
|---|---|---|
| 社内SNS(連絡事項 / タイムライン / チャンネル / 売上報告 / サンクスギフト) | `posts` | 全社員。本文は本人と院長以上、いいね・コメントは誰でも |
| タスク | `tasks` | 担当・作成者・組織図で上の人。自動タスクは `auto_key` で全社 1 行 |
| チャット | `chat_rooms` / `chat_messages` | ルームの参加者だけ(役員以上は全ルーム) |
| 研修とレポート | `trainings` / `training_reports` | 予定は院長以上が作る。提出済みレポートは全員 |
| 始末書・業務改善書 | `incident_reports` | 本人と、組織図で上の人(+本部人事・社長) |
| 売上予算(店舗 × 月) | `budgets` | 全員が読めて、役員以上・本部人事が決める |
| プロフィール写真 | `members.photo_url` + Storage `avatars` | 公開読み取り。書けるのは自分のフォルダだけ |

ダッシュボードは権限ごとに変わります(社長=全体と各店舗 / 管轄者=管轄店舗 / スタッフ=所属店舗と自分の成績)。
売上の「現在・着地見込み・予算比」は売上報告(無い日は日報)から `js/sales.js` が集計します。
